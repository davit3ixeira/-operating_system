EXERCÍCIO 5
------------------------------------------------------------------------------
Enunciado:
Faça um programa que leia 2 números e imprima o resultado das 4 operações
básicas sobre estes 2 números. Verifique o que acontece se o 2º número da
entrada for 0 (zero). Capture o sinal de erro de floating point (SIGFPE) e
repita a experiência anterior.

Código fonte (ex5_sem_signal.c):

#include <stdio.h>

int main (void)
{
    int a, b;

    printf("Digite o primeiro numero: ");
    scanf("%d", &a);
    printf("Digite o segundo numero: ");
    scanf("%d", &b);

    printf("%d + %d = %d\n", a, b, a + b);
    printf("%d - %d = %d\n", a, b, a - b);
    printf("%d * %d = %d\n", a, b, a * b);
    printf("%d / %d = %d\n", a, b, a / b);

    return 0;
}

Linha de comando para compilação e execução:
gcc -o ex5_sem_signal ex5_sem_signal.c
./ex5_sem_signal

Saída gerada (b = 2, sem handler):
Digite o primeiro numero: Digite o segundo numero: 10 + 2 = 12
10 - 2 = 8
10 * 2 = 20
10 / 2 = 5

Saída gerada (b = 0, sem handler):
Digite o primeiro numero: Digite o segundo numero:
Floating point exception
(codigo de saida do processo: 136, ou seja 128 + 8, indicando que o
 processo foi terminado pelo sinal 8 = SIGFPE)

Código fonte (ex5_com_signal.c):

#include <stdio.h>
#include <signal.h>
#include <stdlib.h>
#include <setjmp.h>

jmp_buf ambiente;

void fpeHandler(int sinal);

int main (void)
{
    int a, b;

    signal(SIGFPE, fpeHandler);

    printf("Digite o primeiro numero: ");
    scanf("%d", &a);
    printf("Digite o segundo numero: ");
    scanf("%d", &b);

    if (setjmp(ambiente) == 0) {
        printf("%d + %d = %d\n", a, b, a + b);
        printf("%d - %d = %d\n", a, b, a - b);
        printf("%d * %d = %d\n", a, b, a * b);
        printf("%d / %d = %d\n", a, b, a / b);
        printf("Todas as operacoes foram calculadas com sucesso.\n");
    } else {
        printf("Nao foi possivel calcular a divisao: o handler capturou o SIGFPE.\n");
    }

    return 0;
}

void fpeHandler(int sinal)
{
    printf("Sinal SIGFPE (%d) recebido: divisao por zero detectada!\n", sinal);
    fflush(stdout);
    longjmp(ambiente, 1);
}

Linha de comando para compilação e execução:
gcc -o ex5_com_signal ex5_com_signal.c
./ex5_com_signal

Saída gerada (b = 2, com handler instalado):
Digite o primeiro numero: Digite o segundo numero: 10 + 2 = 12
10 - 2 = 8
10 * 2 = 20
10 / 2 = 5
Todas as operacoes foram calculadas com sucesso.

Saída gerada (b = 0, com handler instalado):
Digite o primeiro numero: Digite o segundo numero: 10 + 0 = 10
10 - 0 = 10
10 * 0 = 0
Sinal SIGFPE (8) recebido: divisao por zero detectada!
Nao foi possivel calcular a divisao: o handler capturou o SIGFPE.
(codigo de saida do processo: 0, ou seja o processo terminou normalmente)

Reflexão:
Sem nenhum tratamento instalado, a divisão inteira por zero (10 / 0) faz o
processador gerar uma exceção de ponto flutuante, que o kernel converte no
sinal SIGFPE. A tabela do slide classifica a ação default de SIGFPE como
"Core": como nenhum handler foi instalado, o processo é terminado
imediatamente (por isso nem "10 / 0 = ..." chega a ser impresso) e o shell
reporta "Floating point exception", com o código de saída 136 (128 + 8),
confirmando que o sinal recebido foi o de número 8 (SIGFPE).
Ao instalar um handler para SIGFPE com signal(), o comportamento muda: a
divisão por zero continua gerando o sinal, mas agora quem trata o evento é
fpeHandler(), que imprime uma mensagem avisando sobre o erro. Um detalhe
importante é que, diferente de um handler "comum" (como o do Exercício 1),
não é seguro simplesmente deixar o handler de SIGFPE retornar normalmente:
a instrução de divisão que gerou a exceção continuaria "quebrada" e o
sinal seria gerado de novo em loop. Por isso o handler usa longjmp() para
desviar a execução de volta para o ponto marcado por setjmp() no main(),
antes da instrução de divisão, evitando repetir a operação inválida e
permitindo que o programa termine de forma controlada em vez de ser
abortado pelo kernel.


EXERCÍCIO 6
------------------------------------------------------------------------------
Enunciado:
Faça um programa para monitorar e informar o preço de chamadas telefônicas.
O programa deverá ser executado em background. O início e o término de uma
chamada são informados através dos sinais SIGUSR1 e SIGUSR2, respectivamente.
O custo da ligação é de 2 centavos por segundo, para ligações de até 1
minuto, ou de 1 centavo por segundo a partir do 2º minuto, ou seja, uma
ligação de 1m30s custa R$1,50.

Código fonte (ex6_monitor_chamadas.c):

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>
#include <time.h>

time_t inicio;
int chamada_ativa = 0;

void iniciaHandler(int sinal);
void terminaHandler(int sinal);

int main (void)
{
    signal(SIGUSR1, iniciaHandler);
    signal(SIGUSR2, terminaHandler);

    printf("PID %d: monitor de chamadas telefonicas aguardando sinais...\n", getpid());
    printf("Envie SIGUSR1 para iniciar uma chamada e SIGUSR2 para encerra-la.\n");
    fflush(stdout);

    for (;;) {
        pause();
    }

    return 0;
}

void iniciaHandler(int sinal)
{
    inicio = time(NULL);
    chamada_ativa = 1;
    printf("Chamada iniciada.\n");
    fflush(stdout);
}

void terminaHandler(int sinal)
{
    if (!chamada_ativa) {
        printf("Nenhuma chamada em andamento no momento.\n");
        fflush(stdout);
        return;
    }

    time_t fim = time(NULL);
    long duracao = (long)(fim - inicio);
    double custo;

    if (duracao <= 60) {
        custo = duracao * 0.02;
    } else {
        custo = 60 * 0.02 + (duracao - 60) * 0.01;
    }

    int minutos = (int)(duracao / 60);
    int segundos = (int)(duracao % 60);

    printf("Chamada terminada. Duracao: %dm%02ds. Custo: R$%.2f\n", minutos, segundos, custo);
    fflush(stdout);

    chamada_ativa = 0;
}

Linha de comando para compilação e execução:
gcc -o ex6_monitor_chamadas ex6_monitor_chamadas.c
./ex6_monitor_chamadas &
kill -s SIGUSR1 <pid>   (inicio da chamada)
kill -s SIGUSR2 <pid>   (fim da chamada)

Saída gerada (chamada curta, ~4 segundos, dentro do primeiro minuto):

Envie SIGUSR1 para iniciar uma chamada e SIGUSR2 para encerra-la.
Chamada iniciada.

Saída gerada (chamada de 1m30s, testando o exemplo do enunciado):
PID 525: monitor de chamadas telefonicas aguardando sinais...
Envie SIGUSR1 para iniciar uma chamada e SIGUSR2 para encerra-la.
Chamada iniciada.
Chamada terminada. Duracao: 1m30s. Custo: R$1.50

Reflexão:
O programa instala handlers para SIGUSR1 e SIGUSR2 e depois fica dormindo
indefinidamente em um laço de pause(), retomando a execução a cada sinal
recebido - exatamente como no exemplo de pause() do slide. Por default, a
tabela do slide classifica a ação de SIGUSR1 e SIGUSR2 como "Term"; sem os
handlers instalados, qualquer um dos dois sinais terminaria o processo
imediatamente. Por isso a instalação dos handlers com signal() é essencial
para que esses sinais sejam reaproveitados como uma forma primitiva de
comunicação entre processos, como descrito na introdução do slide, em vez
de simplesmente matar o monitor.
Ao receber SIGUSR1, iniciaHandler() apenas guarda o instante inicial da
chamada com time(). Ao receber SIGUSR2, terminaHandler() calcula a duração
como a diferença entre o instante atual e o instante salvo e aplica a
tarifa: 2 centavos por segundo para os primeiros 60 segundos e 1 centavo
por segundo a partir do 61º segundo. O teste de 1m30s confirma exatamente
o valor citado no enunciado (R$1,50 = 60s x R$0,02 + 30s x R$0,01), o que
valida a fórmula usada. O programa é pensado para rodar em background (com
"&"), recebendo os sinais de início/fim de chamada de outro processo (por
exemplo, via linha de comando com kill -s), sem nunca terminar sozinho -
teria que ser encerrado externamente (ex: kill -s SIGTERM ou SIGKILL).


EXERCÍCIO 7
------------------------------------------------------------------------------
Enunciado:
Elabore três programas I/O bound que não terminem (loop de mensagens no
vídeo). Elabore um programa que seja capaz de executar os 3 programas
indicados anteriormente e que simule o compartilhamento da CPU entre os 3
processos com escalonamento Round-Robin, com uma fatia de tempo de 1
segundo para o primeiro processo e de 2 segundos para os demais processos.
Execute os programas e relate o que aconteceu.

Código fonte dos processos I/O bound (ex7_io1.c, ex7_io2.c e ex7_io3.c -
idênticos entre si, mudando apenas o rótulo "IO1"/"IO2"/"IO3" impresso):

#include <stdio.h>
#include <unistd.h>

int main (void)
{
    long contador = 0;

    for (;;) {
        contador++;
        printf("Processo IO1 (pid %d): mensagem %ld\n", getpid(), contador);
        fflush(stdout);
        usleep(200000); /* 200 ms - simula uma operacao de E/S */
    }

    return 0;
}

Código fonte do escalonador (ex7_escalonador.c):

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

#define NUM_PROC 3

int main (int argc, char *argv[])
{
    if (argc < 5) {
        fprintf(stderr, "Uso: %s rodadas programa1 programa2 programa3\n", argv[0]);
        exit(-1);
    }

    int rodadas;
    sscanf(argv[1], "%d", &rodadas);

    pid_t pids[NUM_PROC];
    int fatias[NUM_PROC] = {1, 2, 2}; /* 1s para o 1o processo, 2s para os demais */

    for (int i = 0; i < NUM_PROC; i++) {
        pids[i] = fork();

        if (pids[i] < 0) {
            perror("fork");
            exit(1);
        }

        if (pids[i] == 0) {
            char *args[] = { argv[i + 2], NULL };
            execv(argv[i + 2], args);
            perror("execv");
            exit(-1);
        }

        kill(pids[i], SIGSTOP); /* todo mundo comeca parado */
    }

    printf("Escalonador: filhos criados -> IO1 (pid %d), IO2 (pid %d), IO3 (pid %d)\n",
           pids[0], pids[1], pids[2]);
    fflush(stdout);

    for (int rodada = 1; rodada <= rodadas; rodada++) {
        for (int i = 0; i < NUM_PROC; i++) {
            printf("Escalonador: rodada %d -> executando processo %d (pid %d) por %d segundo(s)\n",
                   rodada, i + 1, pids[i], fatias[i]);
            fflush(stdout);

            kill(pids[i], SIGCONT);
            sleep(fatias[i]);
            kill(pids[i], SIGSTOP);
        }
    }

    printf("Escalonador: %d rodadas concluidas. Encerrando os processos filho.\n", rodadas);
    fflush(stdout);

    for (int i = 0; i < NUM_PROC; i++) {
        kill(pids[i], SIGCONT);
        kill(pids[i], SIGKILL);
        wait(NULL);
    }

    printf("Escalonador: todos os filhos finalizados.\n");

    return 0;
}

gcc -o ex7_io3 ex7_io3.c
gcc -o ex7_escalonador ex7_escalonador.c

Reflexão:
O escalonador cria os 3 processos filhos com fork()+execv() (cada um
rodando um dos programas I/O bound, que ficam presos em um laço infinito
imprimindo mensagens a cada 200ms, simulando operações de E/S) e, logo
após cada fork, envia SIGSTOP para o filho recém-criado, deixando todos
parados no início. Em seguida, o laço principal percorre repetidamente os
3 processos aplicando o Round-Robin: para cada um, envia SIGCONT (devolve
o processo ao estado executável, de onde ele havia parado), dorme pela
fatia de tempo correspondente (1s para o processo 1, 2s para os processos
2 e 3, como pedido no enunciado) e então envia SIGSTOP de volta antes de
passar para o próximo processo da fila - implementando o compartilhamento
da CPU sem que os processos I/O bound precisem cooperar entre si.
Dois detalhes interessantes apareceram na execução real: (1) a primeira
mensagem do processo IO1 ("mensagem 1") é impressa antes da linha
"Escalonador: filhos criados", pois existe uma pequena janela de tempo
entre o fork() do primeiro filho e o momento em que o pai consegue enviar
o SIGSTOP inicial - nesse intervalo o filho já está rodando livremente;
(2) depois da última rodada, o processo IO1 ainda imprime mais uma
mensagem ("mensagem 16") durante a fase de encerramento, porque o
escalonador envia SIGCONT antes de SIGKILL para garantir que nenhum
processo fique parado ao ser finalizado - esse SIGCONT dá ao processo uma
última chance de ser escalonado pelo kernel antes que o SIGKILL o mate de
fato. Como esperado, a proporção de mensagens impressas por cada processo
é proporcional à sua fatia de tempo: em cada rodada o processo 1 (fatia de
1s) imprime cerca de 5 mensagens, enquanto os processos 2 e 3 (fatia de 2s
cada) imprimem cerca de 10 mensagens cada, confirmando que o
compartilhamento de CPU via SIGSTOP/SIGCONT respeitou os tempos definidos.
